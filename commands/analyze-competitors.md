Проведи анализ отзывов конкурентов на Wildberries. Аргументы: `$ARGUMENTS`
(первый — файл со ссылками, остальное — параметры сбора, передай их как есть).

Скрипты плагина лежат в `${CLAUDE_PLUGIN_ROOT}/scripts`. Сам ничего не
анализируй и не пиши JSON за субагентов — твоя работа только запускать шаги
и сообщать о результате. Пиши пользователю по-русски и коротко.

## 0. Проверка

- Если `$ARGUMENTS` пустой — попроси указать файл со ссылками и остановись.
- Выполни `uv --version`. Если `uv` не найден — скажи установить его
  (`brew install uv` на Mac или инструкция с https://docs.astral.sh/uv/)
  и остановись.

## 1. Папка запуска

Запуски одного списка лежат вместе — так дашборд показывает динамику.

- `NAME` — имя файла со ссылками без пути и расширения
  (`basename <файл> .txt`; например `шапки.txt` → `шапки`).
- `LIST` = `wb-insights/NAME`.
- `RUN` = `LIST/<результат date +%Y-%m-%d_%H%M%S>`.

Выполни `mkdir -p RUN/data RUN/results`.

## 2. Сбор отзывов

```bash
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/collect.py" $ARGUMENTS --out RUN/data
```

Код выхода 2 — ошибка входного файла: покажи сообщение и остановись.
Код 1 — ни один товар не собрался: покажи причины из вывода и остановись.
Иначе прочитай `RUN/data/_status.json`. Дальше работай только с товарами,
у которых `"status": "ok"`.

## 3. Анализ каждого товара — субагент review-analyst

Для каждого собранного артикула запусти субагента `review-analyst`
(из этого плагина; если требуется полное имя — `wb-review-insights:review-analyst`).
**Не больше 5 одновременно**: отправь до 5 вызовов Agent в одном сообщении,
дождись их и только потом запускай следующие 5.

Задание каждому субагенту (подставь артикул и путь RUN):

```
Артикул: <артикул>
CSV: RUN/data/<артикул>.csv
Meta: RUN/data/<артикул>.meta.json
Записать в: RUN/results/<артикул>.json
```

После каждой пачки проверь каждый результат:

```bash
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/schema.py" result RUN/results/<артикул>.json --csv RUN/data/<артикул>.csv
```

Если проверка не прошла — запусти этого субагента **ещё один раз**, добавив
к заданию строку «Ошибки прошлой попытки:» и весь вывод проверки. Если и вторая
попытка не прошла — убери файл из анализа:
`mv RUN/results/<артикул>.json RUN/results/<артикул>.json.invalid`
и запомни этот артикул как «ошибка анализа». Остальные товары продолжай.

Если ни одного валидного результата нет — сообщи об этом и остановись.

## 4. Сводка по нише — субагент insights-writer

Сначала получи словарь тем прошлого запуска по этому же списку:

```bash
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/dashboard.py" LIST --vocab-for RUN
```

Запусти субагента `insights-writer` (`wb-review-insights:insights-writer`)
с заданием:

```
Папка results: RUN/results
Записать в: RUN/results/summary.json
<весь вывод команды выше — словарь тем или фраза, что его нет>
```

Проверь:

```bash
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/schema.py" summary RUN/results/summary.json
```

При ошибках — один повтор с «Ошибки прошлой попытки:» и выводом проверки.
Если снова ошибки — продолжай без сводки (отчёт построится по конкурентам).

## 5. Отчёт и дашборд

```bash
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/report.py" --run RUN
uv run "${CLAUDE_PLUGIN_ROOT}/scripts/dashboard.py" LIST
```

Если дашборд не построился (например, ошибка в `wb-insights/dashboard.toml`),
сообщи причину из вывода, но не считай весь запуск неудачным — отчёт уже готов.

## 6. Ответ пользователю

Коротко, без таблиц:

1. Пути к отчёту `RUN/report.xlsx` и дашборду `LIST/dashboard.html`
   (открывается в браузере двойным кликом).
2. `chat_summary` из `RUN/results/summary.json` (если сводка есть) и топ жалоб
   из вывода report.py — числа бери оттуда, сам не пересчитывай.
3. Сколько сравнимых запусков в динамике (из вывода dashboard.py). Если это
   первый запуск списка — скажи, что динамика появится со следующего.
4. Что не вошло в отчёт: товары с ошибкой сбора (из `_status.json`, с причиной)
   и с ошибкой анализа. Если всё прошло — так и скажи одной строкой.
5. Одной строкой: настройки дашборда — в `wb-insights/dashboard.toml`,
   пересобрать после правки — `/wb-dashboard NAME`.
